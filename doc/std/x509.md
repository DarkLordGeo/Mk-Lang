# std.x509

`std.x509` reads X.509 certificates (RFC 5280) from DER or PEM and checks that a chain leads from a TLS server's certificate to a root you trust. It also loads the system's trusted roots. [`std.tls`](tls.md) uses it for every client handshake; use it directly to inspect certificates, or to check a server's chain at a time you choose. `Verify` checks a chain for TLS server use only.

No outside security review has checked `std.x509` yet, so it is [Experimental](README.md#9-stability). Read the [library guide](README.md) first.

```mk
// verdict: parse
import std.x509
```

## The main pieces

| Task | Use |
|---|---|
| Read one DER certificate | `Parse` |
| Read every certificate of a PEM text | `ParsePem` |
| Facts about a certificate | `Certificate.Subject`, `Issuer`, `Names`, `NotBefore`, `NotAfter`, `PublicKey`, `Der` |
| Roots you choose | `Pool.New` |
| The system's roots | `SystemPool` (loaded once per process) or `SystemRoots` (read each call) |
| Check a server's chain | `Verify` |

## Certificates

A `Certificate` is a set of views of its DER. `Parse` checks the whole structure and records where each part is. The subjectAltName and name constraints are read from the DER when a check needs them. So a certificate owns nothing, is plain, `Send` and `Share`, and lives as long as the bytes it was parsed from. Only `Parse` and `ParsePem` make one.

- `Parse` reads one DER certificate with nothing after it, and fails with `Malformed(offset)` at the first byte that is not RFC 5280's structure. It never panics on its input, uses no recursion, and allocates nothing.
- `ParsePem` reads every `CERTIFICATE` block of a PEM text, in order, and skips text outside the blocks and blocks with other labels. It copies each certificate's DER into the arena.
- `Subject` and `Issuer` give the distinguished name as RFC 4514 text, such as `CN=ed.test`.
- `Names` gives the subjectAltName's DNS names and IP addresses: the names `Verify` matches a host against.
- A validity time outside `time.Time`'s range saturates to that end of the range, and so does RFC 5280's no-expiry value, `99991231235959Z`.
- `PublicKey` reads the subject's key with `crypto.ParsePublicKey`: a P-256 or P-384 point, an RSA key of at least 2048 bits, or an Ed25519 key.

## Verifying a chain

`Verify(a, io, chain, roots, now, host)` checks `chain`, the server's certificate first and then any intermediates in any order, for a TLS server named `host` at the time `now`. It builds paths by RFC 5280, with name constraints, key usage, basic constraints and validity. It does no policy processing and no revocation checking.

- **The name.** `host` is matched against the leaf's subjectAltName only, never its common name. An IP address, bare or in brackets, matches the IP names. An empty `host` is not checked.
- **The leaf's use.** Where key usage is present it must allow `digitalSignature`; where an extended key usage is present it must allow `serverAuth` or any use.
- **The path.** Every certificate is valid at `now`. Every issuer is a CA, with `keyCertSign` where key usage is present, and a path length that allows what is below it. Every name below an issuer is within its name constraints.
- **Signatures.** Each signature of the path is by SHA-256, SHA-384 or SHA-512 (ECDSA, RSA PKCS #1 v1.5 or RSA-PSS) or by Ed25519, and verifies. RSA-PSS must use the message's hash for MGF1, a salt as long as the hash, and trailer field 1. SHA-1 and MD5 signatures are refused, and so is an algorithm std.x509 does not know, which `Parse` accepts. A weak signature the path does not use, such as an unused SHA-1 cross-signature, or a root's own, is not checked.
- **URI constraints.** Under a URI name constraint, a URI subjectAltName is matched only when every URL reader reads its authority alike. That means RFC 3986 bytes, one `@`, no `%` or `\` in the host, and no control byte. Any other is refused.
- **Limits.** After 100 signature checks, or 2^20 units of name-constraint work, `Verify` gives up with `TooComplex`. A hostile chain cannot make it run long.

`Verify` does not check the size of the leaf's key. `tls.Client` reads it with `Certificate.PublicKey`, which refuses an RSA key under 2048 bits.

## The system's roots

A pool you make with `Pool.New` is checked by `std.x509` alone. The system's pool depends on the target:

- **Linux.** `SystemRoots` reads the file `SSL_CERT_FILE` names, else the first that exists of `/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/ssl/ca-bundle.pem`, `/etc/pki/tls/cacert.pem`, `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem` and `/etc/ssl/cert.pem`. Then it reads every file of the directories `SSL_CERT_DIR` lists, separated by colons, else of `/etc/ssl/certs`, `/etc/pki/tls/certs` and `/system/etc/security/cacerts`, in name order. It skips what does not parse, a file over 64 MiB and a link to a file of the same directory. It also skips a file or directory it cannot open, read or list. It keeps each certificate once.
- **Windows.** The pool lists no certificates and stands for the system. `Verify` hands the chain to the platform's chain check, on a pool thread through `io`, and still checks the name and the leaf's key usage itself.

On Windows the platform is asked for strong signatures (`szOID_CERT_STRONG_SIGN_OS_1`), so these fail with `Unsupported`:

- a SHA-1, MD5 or MD2 signature on the leaf, or on the path the platform builds;
- an RSA key shorter than 2047 bits on a certificate above the leaf on that path;
- an Ed25519 key above the leaf, which the platform cannot check. A pool of your own accepts it.

A weak certificate the platform's path does not use, such as an unused cross-signature, is not refused.

**Loading once.** `SystemPool` is `SystemRoots`' pool, loaded once per process. The first call that finds a certificate keeps the pool, and every later call returns it without reading the store again. So on Linux a later change to the bundle, or to `SSL_CERT_FILE` and `SSL_CERT_DIR`, is not seen; on Windows the platform reads its store at each `Verify`.

- Calls on several tasks make one load, and the others wait for it.
- A load that fails (`Canceled`, `OutOfMemory`) or finds no certificate keeps nothing, and the next call loads again.
- The kept pool lives in one block of the process heap that is never freed, as the heap itself is not. A test build's leak count does not count it.
- Under a simulated or taped `Io` (a `Sim`'s, a `Recorder`'s or a `Replayer`'s), `SystemPool` fails with `Unsupported`, since that `Io`'s files are not the process's to keep. `SystemRoots` reads them through the `Io`, from its own disk and environment. Under a simulated `Io` the platform's verdict is `Unsupported` too.

## Errors

Every function fails with members of `x509.Error`:

| Member | Meaning |
|---|---|
| `Malformed(offset)` | The input is not a certificate std.x509 reads; `offset` is the first faulty byte of the DER or the PEM text |
| `UnknownAuthority` | No path from the chain leads to a certificate of the pool, or the chain is empty |
| `Expired` | A certificate of the path is not valid at the time given |
| `NameMismatch` | `host` is not one of the leaf's subjectAltName names |
| `BadSignature` | A signature of the path does not verify under its issuer's key |
| `BadUsage` | A certificate may not be used so: an issuer that is not a CA or lacks `keyCertSign`, a path too long for an issuer's path length, a name outside an issuer's name constraints, or a leaf whose key usage or extended key usage does not allow a TLS server |
| `TooComplex` | `Verify` gave up: 100 signature checks, 2^20 units of name-constraint work, or a chain over 16 certificates for the platform's check |
| `Unsupported` | A signature or key the path needs that std.x509 does not support (SHA-1 and MD5 among them), an unhandled critical extension, a target with no system store, or the platform's refusal |
| `Canceled` | The call's scope was cancelled |
| `OutOfMemory` | The arena or the heap is full |

`x509.Error` is open, so a `match` on it outside std keeps a `_` arm. Through `tls.Error` these errors reach a TLS client, and through `net.SecureFailed(why)` an `https` client.

## Memory, cost and cancellation

- `Parse` allocates nothing and is O(der). `ParsePem` copies each certificate's DER into the arena.
- `Verify` allocates the constraint sets of one issuer at a time in a sub-arena of `a`, freed after. Its cost is bounded by its limits.
- `SystemRoots` puts the certificates and the pool in the arena you pass, reading one file at a time.
- `Verify`, `SystemRoots` and `SystemPool` lose nothing on `Canceled`: call them again. `Verify` is cancelled only before the platform's check starts.

## Examples

### Check a chain

Parse a root and a leaf, look at the leaf, and check the chain at a fixed time for two host names and at a time before the leaf was valid.

```mk
// verdict: ok
import std.time
import std.x509

// A root and a leaf it signed, both Ed25519. A program reads these from
// files; here they are inline.
const RootPem = """
    -----BEGIN CERTIFICATE-----
    MIIBVjCCAQigAwIBAgICA+8wBQYDK2VwMDExEDAOBgNVBAoTB01rIHRlc3QxHTAb
    BgNVBAMTFE1rIFRlc3QgRWQyNTUxOSBSb290MCAXDTAwMDEwMTAwMDAwMFoYDzIy
    MDAwMTAxMDAwMDAwWjAxMRAwDgYDVQQKEwdNayB0ZXN0MR0wGwYDVQQDExRNayBU
    ZXN0IEVkMjU1MTkgUm9vdDAqMAUGAytlcAMhAIfLhpvy8aeqWOrFL+2fMjovo1yx
    EhJY+u1+VkWeF03ro0IwQDAOBgNVHQ8BAf8EBAMCAQYwDwYDVR0TAQH/BAUwAwEB
    /zAdBgNVHQ4EFgQUE5zasbHoZgTtFEi8P8Pa74aH0WQwBQYDK2VwA0EAsHOt4A21
    WyQBHQet1Sd89tdHXqkJ9Gpbj4SNN9D3/GYv1Y/WOz7Jvy0mbh6S0FJVV6LlAEF/
    t41s0/75axH6AQ==
    -----END CERTIFICATE-----
    """

const LeafPem = """
    -----BEGIN CERTIFICATE-----
    MIIBUTCCAQOgAwIBAgICA/AwBQYDK2VwMDExEDAOBgNVBAoTB01rIHRlc3QxHTAb
    BgNVBAMTFE1rIFRlc3QgRWQyNTUxOSBSb290MCAXDTAwMDEwMTAwMDAwMFoYDzIy
    MDAwMTAxMDAwMDAwWjASMRAwDgYDVQQDEwdlZC50ZXN0MCowBQYDK2VwAyEANZGu
    1WcDWx1L1QTKufPBzkjlkYOK3pMdCbHtEb5H7K6jXDBaMA4GA1UdDwEB/wQEAwIH
    gDATBgNVHSUEDDAKBggrBgEFBQcDATAfBgNVHSMEGDAWgBQTnNqxsehmBO0USLw/
    w9rvhofRZDASBgNVHREECzAJggdlZC50ZXN0MAUGAytlcANBANSLA3BbFrwC/K8R
    ePl0Gfq+r3ygkNp6kYx8PxouxT1Be2r81Q/y7mor+s1M6LL3QBpU3t3G5g/SFe+f
    WpaOlgU=
    -----END CERTIFICATE-----
    """

Check(sys: &System, chain: []x509.Certificate, roots: &x509.Pool, now: time.Time, host: str): WriteError!void {
    x509.Verify(sys.arena, sys.io, chain, roots, now, host) else e {
        try sys.Print("{host}: refused, {e}\n", (host, e))
        return
    }
    try sys.Print("{host}: trusted\n", (host))
}

export Main(sys: &System): x509.Error|WriteError!void {
    roots := try x509.ParsePem(sys.arena, RootPem)
    chain := try x509.ParsePem(sys.arena, LeafPem) // the leaf first, then any intermediates
    leaf := &chain.Items()[0]
    subject := try leaf.Subject(sys.arena)
    issuer := try leaf.Issuer(sys.arena)
    names := try leaf.Names(sys.arena)
    try sys.Print("subject: {subject}\nissuer:  {issuer}\n", (subject, issuer))
    for name in names.Items() {
        try sys.Print("name:    {name}\n", (name))
    }
    try sys.Print("valid:   {from} to {to}\n", (from: leaf.NotBefore(), to: leaf.NotAfter()))

    pool := x509.Pool.New(roots.Items())
    now := time.FromUnix(1_800_000_000, 0) // a fixed time, so the output does not change
    try Check(sys, chain.Items(), &pool, now, "ed.test")
    try Check(sys, chain.Items(), &pool, now, "other.test")
    try Check(sys, chain.Items(), &pool, time.FromUnix(0, 0), "ed.test") // 1970
}
```

```text
$ mk run check.mk
subject: CN=ed.test
issuer:  CN=Mk Test Ed25519 Root,O=Mk test
name:    ed.test
valid:   2000-01-01T00:00:00Z to 2200-01-01T00:00:00Z
ed.test: trusted
other.test: refused, NameMismatch
ed.test: refused, Expired
```

- `Verify` takes the time to check against, so a test or a tool can check a chain at any moment. `tls.Client` passes the wall clock.
- A refused chain is an error value; `{e}` prints its name.
- The certificates are views of the PEM text's DER in `sys.arena`.

### Read a bundle

```mk
import std.crypto

    BgNVBAMTFE1rIFRlc3QgRWQyNTUxOSBSb290MCAXDTAwMDEwMTAwMDAwMFoYDzIy

    1WcDWx1L1QTKufPBzkjlkYOK3pMdCbHtEb5H7K6jXDBaMA4GA1UdDwEB/wQEAwIH
    gDATBgNVHSUEDDAKBggrBgEFBQcDATAfBgNVHSMEGDAWgBQTnNqxsehmBO0USLw/
    w9rvhofRZDASBgNVHREECzAJggdlZC50ZXN0MAUGAytlcANBANSLA3BbFrwC/K8R
    ePl0Gfq+r3ygkNp6kYx8PxouxT1Be2r81Q/y7mor+s1M6LL3QBpU3t3G5g/SFe+f
    WpaOlgU=
    -----END CERTIFICATE-----
    """

KeyName(k: crypto.PublicKey): str {
    return match k {
        .Ec { "EC" }
        .Rsa { "RSA" }
        .Ed25519 { "Ed25519" }
    }
}

export Main(sys: &System): x509.Error|fs.Error|crypto.Error|WriteError!void {
    try fs.WriteAll(sys.io, "bundle.pem", Bundle.AsBytes())
    text := try fs.ReadText(sys.arena, sys.io, "bundle.pem")
    certs := try x509.ParsePem(sys.arena, text) // every CERTIFICATE block, in order
    for cert in certs.Items() {
        subject := try cert.Subject(sys.arena)
        key := try cert.PublicKey()
        try sys.Print("{subject}: {key} key, {n} bytes of DER, until {end}\n", (subject, key: KeyName(key), n: cert.Der().Len(), end: cert.NotAfter()))
    }
    try fs.Remove(sys.io, "bundle.pem")
}
```

```text
$ mk run bundle.mk
CN=Mk Test Ed25519 Root,O=Mk test: Ed25519 key, 346 bytes of DER, until 2200-01-01T00:00:00Z
CN=ed.test: Ed25519 key, 341 bytes of DER, until 2200-01-01T00:00:00Z
```

- `ParsePem` skips text between the blocks, so a bundle with comments reads as well.
- `PublicKey` returns a `crypto.PublicKey`, an enum of the key kinds std.crypto reads.

### Trust the system's roots

Check a chain the way `tls.Client` does with `DefaultConfig`. The system's store differs from machine to machine, so this block only compiles and has no output to show.

```mk
// verdict: ok
import std.time
import std.x509

// Trusted checks chain for host against the system's roots, at the wall
// clock. The pool is loaded once per process and kept.
Trusted(h: &Heap, a: &Arena, io: Io, chain: []x509.Certificate, host: str): x509.Error!bool {
    roots := try x509.SystemPool(h, io)
    x509.Verify(a, io, chain, roots, time.Wall(io), host) else e {
        match e {
            x509.UnknownAuthority { return false }
            x509.Expired { return false }
            x509.NameMismatch { return false }
            _ { fail e } // BadSignature, BadUsage, Canceled, ...
        }
    }
    return true
}
```

- `SystemPool` reads the store once and keeps it, so calling it for every chain costs one uncontended lock after the first.
- Under a simulated `Io`, call `SystemRoots` instead: `SystemPool` fails there with `Unsupported`.

### `Certificate.NotBefore`

```
export Certificate.NotBefore(&self): time.Time
```

The start of the validity period. A time outside Time's range

### `Parse`

```
export Parse(a: &Arena, der: []u8): Error!Certificate from a, der
```

- Flows: The result borrows from a and der.
- Errors: Error (Canceled, OutOfMemory, BadSignature, BadUsage, Expired, Malformed(offset: int), NameMismatch, TooComplex, UnknownAuthority, Unsupported)

Reads one DER certificate with nothing after it. The result is a set of
views of der, so der must outlive it. O(der) with no recursion;
allocates nothing; never panics on input.

Fails with Malformed at the first byte that is not RFC 5280's
structure: a DER fault, a version above 3, a negative serial, inner and
outer signature algorithms that differ, a validity time that is not
UTCTime or GeneralizedTime in seconds with Z, or an extension outside
version 3 or repeated. These extensions fail it when malformed: basic
constraints, key usage, extended key usage, subjectAltName, name
constraints, key identifier, CRL distribution points, certificate
policies (more than 64 included), policy mappings, policy constraints,
inhibitAnyPolicy and authority information access. So do an object
identifier that is not minimal, a constructed or malformed unique
identifier, and a key identifier or authority information access
extension marked critical. A time outside time.Time's range saturates.

### `ParsePem`

```
export ParsePem(a: &Arena, pem: str): Error!List[Certificate] from a
```

- Flows: The result borrows from a.
- Errors: Error (Canceled, OutOfMemory, BadSignature, BadUsage, Expired, Malformed(offset: int), NameMismatch, TooComplex, UnknownAuthority, Unsupported)

The certificates of every CERTIFICATE block of pem, in order. Text
outside the blocks, and blocks with other labels, are skipped. O(pem);
allocates the list and each certificate's DER in a, and one block's
decoding at a time.

Fails with Malformed when a block is not RFC 7468's or its DER is not a
certificate. The offset is the block's begin line, or the fault inside
the base64 where std.encoding names one. Fails with OutOfMemory too.


A set of trusted certificates: the roots Verify may end a path at. A
plain view of a slice of certificates, Send and Share. Only New and
SystemRoots make one. A pool from New is checked by std.x509 alone; the
system's pool on Windows hands the chain to the platform.

Fields:

- `certs: []Certificate`: The certificates, as New was given them.

### `Pool.New`

```
export Pool.New(certs: []Certificate): Pool from certs
```

- Flows: The result borrows from certs.

A pool of certs, as a view of them. O(1); allocates nothing.

### `SystemPool`

```
export SystemPool(h: &Heap, io: Io): Error!&Pool
```

- Errors: Error (Canceled, OutOfMemory, BadSignature, BadUsage, Expired, Malformed(offset: int), NameMismatch, TooComplex, UnknownAuthority, Unsupported)

The system's trusted roots, loaded once for the process: the pool
SystemRoots gives, read by the first call that finds a certificate and
kept, so every later call returns the same pool without reading the
store again. O(1) once kept (one uncontended lock); else SystemRoots'
cost and one copy of the certificates.

On Linux a later change to the bundle, or to SSL_CERT_FILE and
SSL_CERT_DIR, is not seen. On Windows the pool stands for the platform,
which reads its store at each Verify.

Calls on several tasks make one load; a call that finds another loading
waits for it. A load that fails (Canceled, OutOfMemory) keeps nothing
and leaves nothing allocated. A load that finds no certificate is not
kept either: it returns an empty pool, and the next call loads again. A
file or directory that is missing or cannot be opened, read or listed
(any std.fs error but Canceled) is skipped, as SystemRoots skips it, and
a load that found a certificate is kept without it.

Memory: the kept pool lives in one block of h, the process heap, never
freed: the Pool, its certificates and their DER, at most once per
process (and one empty pool). A test build's leak count does not count
it. The load's own memory is in an arena of h, freed before it returns.

Fails with Unsupported on a target with no system store, and under a
simulated or taped Io (a Sim's, Recorder's or Replayer's), whose files
are not the process's to keep: call SystemRoots there. Fails with
Canceled in a cancelled scope, since taking the lock can be cancelled,
or in the load (nothing is consumed; call again), and with OutOfMemory.

### `SystemRoots`

```
export SystemRoots(a: &Arena, io: Io): Error!Pool from a
```

- Flows: The result borrows from a.
- Errors: Error (Canceled, OutOfMemory, BadSignature, BadUsage, Expired, Malformed(offset: int), NameMismatch, TooComplex, UnknownAuthority, Unsupported)

Loads the system's trusted roots into a pool. Each call reads the store
again; SystemPool loads it once per process. O(bundle bytes + d log d
name comparisons for a directory of d entries + n log n DER comparisons
for n certificates); allocates the certificates' DER and the pool in a,
and one directory's names and one file's bytes at a time in sub-arenas
freed after.

On Linux it reads the file SSL_CERT_FILE names, else the first of the
usual bundle files that exists, then the files of the directories in
SSL_CERT_DIR (colon-separated), else of the usual directories, each
directory's files in name order. It skips what does not parse, a file
past 64 MiB and a link to a file of the same directory, and keeps each
certificate once, first seen first. A missing file or directory, and one
that cannot be listed to its end, is skipped, so a system with none
gives an empty pool. Files are read through io, so a simulated Io reads
its own disk and environment.

On Windows the pool lists nothing and stands for the system: Verify
hands the chain to the platform's check.

Fails with Unsupported on a target with neither, with Canceled (any
std.fs wait; nothing is consumed, so a second call reads the same), and
with OutOfMemory.

### `TooComplex`

```
export error TooComplex
```

Verify gave up: 100 signature checks, or 2^20 units of name-constraint
work, did not settle the chain, or the chain handed to the platform's
check is longer than 16 certificates.

### `UnknownAuthority`

```
export error UnknownAuthority
```

No path from the chain leads to a certificate of the pool.

### `Unsupported`

```
export error Unsupported
```

The path needs what std.x509 does not support: a signature by SHA-1 or
MD5 (refused), a key or signature algorithm std.crypto lacks, an
unhandled critical extension, or a platform verifier the target lacks.
On Windows it is also the platform's refusal of a weak signature or
key.

### `Verify`

```
export Verify(a: &Arena, io: Io, chain: []Certificate, roots: &Pool, now: time.Time, host: str): Error!void
```

- Errors: Error (Canceled, OutOfMemory, BadSignature, BadUsage, Expired, Malformed(offset: int), NameMismatch, TooComplex, UnknownAuthority, Unsupported)

Checks that chain, the leaf first and then any intermediates in any
order, is a valid certificate chain for a TLS server named host at the
time now, ending at a certificate of roots. It builds paths by RFC 5280,
with name constraints, key usage, basic constraints and validity, and
without policy processing or revocation. O(100 signature checks +
(pool + chain) per step + (k + names) log k per constrained issuer of a
complete path); allocates the sorted constraint sets of one issuer at a
time in a sub-arena of a, freed after, and the platform's request.

The leaf: host must match one of its subjectAltName names; the subject's
common name is never used. An IP address, bare or in brackets, matches
its IP names; an empty host is not checked. Where present, its key
usage must allow digitalSignature and its extended key usage serverAuth
or any.

The path: every certificate valid at now; every issuer a CA, with
keyCertSign where key usage is present and a path length that allows
what is below it; every name below an issuer within its name
constraints; every signature by SHA-256, -384 or -512, or Ed25519, and
verifying. SHA-1 and MD5 signatures are refused. Under a URI name
constraint, a URI name is matched only when every URL reader reads its
authority alike: RFC 3986 bytes, one `@`, no `%` or `\` in the host, no
control byte; any other is refused. A weak signature the path does not
use, such as an unused SHA-1 cross-signature, or a root's own, is not
checked. Verify does not check the size of the leaf's key: tls.Client
calls Certificate.PublicKey, which refuses an RSA key under 2048 bits.

With the pool SystemRoots gives on Windows, the leaf is checked as
above and the chain is handed to the platform's check, on a pool thread
through io. The platform is asked for strong signatures
(`szOID_CERT_STRONG_SIGN_OS_1`), so these are Unsupported: a SHA-1, MD5
or MD2 signature on the leaf or on any certificate of the path the
platform builds; an RSA key shorter than 2047 bits on a certificate
above the leaf on that path; and an Ed25519 key above the leaf, which
the platform cannot check. A program's own pool accepts that last one.

Fails with NameMismatch, BadUsage, Expired, BadSignature, Unsupported,
UnknownAuthority (no path, or an empty chain), TooComplex (the 101st
signature check, 2^20 units of name-constraint work, or a chain over 16
certificates on the platform's path), Canceled (only before the
platform's check starts) and OutOfMemory.
